## FR-26: Verify-Completion-Gate, Sent-Sync-Coverage und Read-Eskalations-Reason

**Status:** ⬜ geplant. Drei Befunde aus Batch 2026-W40/1 (2026-09-27,
boku-user, 10 Items, 3× `keep_in_folder`, `--sync-sent 150`):

### Problem & Motivation

1. **MD-V1 — keep-Items blockieren Completion:** `verify.py:168–206` prüft
   Evidenz für **jedes** Item; `keep_in_folder`/unknown-Items haben kein
   Evidenz-Zuhause → Fallback-Volltextsuche in `memory/evidence/**/*.md`
   findet nichts → `in_evidence=False` → `all_consistent=False` →
   `recovery_required` → `release_synthesis_handoff` (`completion.py:30–37`,
   verlangt `ok is True` + alle `consistent is True`) lässt den Handoff leer.
   Beobachtet: verify → `PartialFailure/recovery_required`, read-only
   `reconcile` (evidence optional) → `completed` + Handoff released — die
   Completion-Pfade widersprechen sich. Der Scope-Zwang
   (`_verified_execute_candidate`, `verify.py:58–60`: `result_ids ==
   verify_scope_ids`) verhindert eine verkürzte Verifikation.
2. **MD-SE1/MD-SE2 — Sent-Sync-Coverage-Lücke:** `--sync-sent 150` untersuchte
   „7 Envelopes", `sent-index.jsonl` blieb auf `updated_at` 2026-09-11
   (16 Tage vor dem Lauf): `sync_sent_items` (`sent_indexer.py:271–289`)
   ignoriert `count` im No-Dates-Pfad komplett (fest `range(7)`, Rückgabe =
   `len(recent_dates)` — Datums-Buckets, keine Envelopes; Telemetriename
   `total_envelopes_examined` irreführend). `sync_sent_items_by_date`
   (`:148–189`) fragt je Tag 1× `envelope list -s 100` ohne Pagination; der
   Zeitraum zwischen letztem Index-Eintrag (Watermark) und dem 7-Tage-Fenster
   (hier 2026-09-12…09-19) bleibt **ungeprüft** — der Sync kann die
   Abwesenheit von Sent-Replies für die Batch-Mails nicht belegen (genau das,
   wovor SKILL Schritt 9 warnt). `except Exception: return 0` (`:181–182`)
   tarnt Himalaya-Fehler als „0 neue Mails" bei `ok: true` — zu weich für
   einen fail-closed Reply-Evidenz-Preflight.
3. **MD-A5 — review_reason fehlt:** `_full_read_failure`
   (`classifier.py:138–157`) setzt `confidence: low`, `review_required: True`,
   `read_escalation.status: failed`, `keep_in_folder` — aber **kein**
   `review_reason` (Vergleich: `do_not_route_suppressed` `:615`,
   `attachment_inventory_unavailable` `:735`,
   `untrusted_attachment_extractions_without_inventory` `:807`). Maschinelle
   Triage sieht die Ursache nicht; der Agent formuliert selbst für
   `pending-review.jsonl`.

### Ziel & Invarianten

- **MD-V1 (Disposition a+c):** `keep_in_folder`/unknown-Items werden von der
  Evidenzpflicht ausgenommen — Verify prüft für sie Index/Log/Ordner
  (kein Move passierte, kein Evidenz-Nachweis nötig); Evidenzprüfung bleibt
  Pflicht für verschobene Items. `in_evidence` für keep-Items = `null`
  (nicht geprüft, nicht fehlgeschlagen). Completion-Pfade konsistent:
  ein Batch mit keep-Items schließt regulär über `verify`; `reconcile` bleibt
  Recovery-Pfad. Doku-Zeile in batch-runner.md („Batches mit keep-Items
  schließen regulär über verify"). Option (b) „kanonisches Evidenz-Zuhause"
  bewusst NICHT — neue Policy gehört zu FR-09 (Cloud-Handoff).
- **MD-SE1 (Sent-Sync-Fenster + fail-closed):** No-Dates-Pfad leitet das
  Fenster aus dem Index-Watermark ab (letztes indizierte Sent-Datum → heute,
  min. 1 Tag, Capping gegen Endlosschleifen, z. B. max. 60 Tage pro Lauf mit
  dokumentiertem Follow-up-Hinweis); `count` wird respektiert (N neueste
  Tage/Envelopes via Paging `-s 100` + Offset/Seite); Per-Datum-Fehler
  propagieren (fail-closed: `sync_failed` + Fehlerliste im Envelope, kein
  stiller `ok: true`).
- **MD-SE2 (Telemetrie):** `date_windows_synced` (Buckets) und echte
  `envelopes_examined` getrennt; `total_envelopes_examined` wird korrekt
  befüllt oder ersetzt (Doku + Tests mitziehen).
- **MD-A5:** `_full_read_failure` setzt
  `decision["review_reason"] = "read_escalation_failed"`; Vokabular in der
  SKILL.md/`pending-review`-Doku ergänzt; bestehende read_escalation-Tests
  mitziehen.
- Weiterhin: null Mailbox-Mutationen im Sent-Sync (read-only), fail-loud
  Account-Bindung unverändert, keine neuen Mailbox-Semantiken.

### Abnahme

- Hermetische Tests: (a) verify schließt Batch mit keep-Items regulär
  (`ok: true`, Handoff released), verschobene Items weiterhin voll geprüft;
  (b) Sent-Sync nutzt Watermark-Fenster (Lücke 2026-09-12…09-19 würde
  gedeckt), `count` respektiert, Per-Datum-Fehler → `ok: false` +
  `sync_failed`, Telemetrie getrennt; (c) `_full_read_failure` trägt
  `review_reason: "read_escalation_failed"`.
- Bestehende verify/sync_sent-Tests, die heutiges Verhalten pinnen
  (`range(7)`-Fenster, `total_envelopes_examined`-Semantik), werden bewusst
  angepasst (dokumentiert).
- Suite grün; System-Map/Referenzdoku aktualisiert (batch-runner.md sync-sent-
  Sektion, SKILL.md Schritt-9-Kontext falls betroffen).
